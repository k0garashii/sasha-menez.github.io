    RTTR + JSON

    Réflexion & Sérialisation

    Conçue par Ugo Szemberg avec l'architecture du projet, c'est la brique invisible qui fait tenir le reste : grâce à la réflexion, un composant déclaré une fois est à la fois affiché dans l'inspecteur, sauvegardé dans la scène et restauré après le mode play.

    • RTTR
    • nlohmann/json
    • UUID
    • Prefabs

    Déclarer une fois

    Une seule déclaration, trois usages

    Chaque composant enregistre ses propriétés dans RTTR, accompagnées d'une métadonnée UIData qui décrit comment l'éditer (champ glissant, entier, case à cocher, vecteur, couleur, référence d'objet...).

    rttr::registration::class_<SoundEmitter>("SoundEmitter")
    .constructor<>()(rttr::policy::ctor::as_raw_ptr)
    .property("Volume", &SoundEmitter::GetVolume, &SoundEmitter::SetVolume)
        (rttr::metadata(UI_DATA_METADATA_KEY, UIData(EUIType::DRAG_FLOAT, 0.f, 20.f)));

    Inspecteur

    L'éditeur parcourt les propriétés et choisit le widget d'après la métadonnée, sans code d'UI propre au composant.

    Sauvegarde

    Le sérialiseur parcourt les mêmes propriétés, récursivement, pour écrire et relire le JSON.

    Scripts

    Les scripts utilisateur passent par le même chemin, avec une réflexion générée à la compilation.

    Fichiers

    Ce qui est sauvegardé

    Fichier Contenu
    .sceneHiérarchie des objets et leurs composants, skybox, position de la caméra d'édition.
    .scriptScripts attachés et valeurs de leurs propriétés, rangés par UUID d'objet.
    .prefabUn objet et tous ses enfants, réinstanciable dans n'importe quelle scène.
    .matParamètres et textures d'un matériau, édités dans le material editor.

    Les scripts sont volontairement stockés à part : ils vivent dans une DLL rechargeable, et les séparer de la scène permet de les réattacher après un hot reload sans recharger le reste.

    Mode play

    Jouer sans rien casser

    Comme dans Unity, tout ce qui change pendant une partie de test (positions, valeurs de scripts, objets détruits) doit disparaître quand on arrête le jeu.

    1. PlaySaveBeforePlay écrit la scène dans un fichier temporaire.
    2. PartiePhysique, scripts et audio modifient librement la scène.
    3. StopResetAfterPlay vide la scène et la reconstruit depuis le fichier temporaire.
    4. RéattacheLes scripts sont recollés aux objets, puis le fichier temporaire est supprimé.

    Recul

    Limites et suite

    Format binaire

    Le JSON est lisible et pratique à déboguer, mais lourd pour un build final. Un format binaire pour l'exécutable de jeu accélérerait le chargement.

    Versionnage

    Les fichiers ne portent pas de numéro de version : renommer une propriété peut rendre une ancienne scène illisible. Un système de migration serait la prochaine étape.
